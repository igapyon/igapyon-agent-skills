# Activity の履歴から作業を再開する

「11月20日に考えていた daybook の記録方式、その続きをやりたい」という依頼から再開できるようにする。利用者が覚えている日付や話題で入口を探し、作業のつながりをさかのぼって、当時の判断と残件を読み直す。途中で使うエージェントが変わっても、daybook の Markdown と同梱の Node.js CLI で同じ経緯を読めるようにする。

**推奨案は、activity に任意の「前回の記録」を一つ持たせ、これを使った再開を提供してから、waypoint の作成・状態管理を廃止すること。** 現行仕様でも activity 単独で再開できる。今回加えるのは、並行作業の中から入口を選ぶ手段と、過去のどの記録から作業を引き継いだかを機械的にたどる約束である。[現行の再開手順](../../skills/igapyon-miku-daybook/references/waypoints.md#find-and-resume-earlier-work)

## 1. Activity に記録する関係

「前回」は、この activity で実際に続きを引き継いだ一件を指す。同じスレッドで話題を切り替えれば別の作業になり、別のエージェントでも前回の続きを引き受ければ同じ流れになる。日付、英字の連番、セッション ID だけから前回を推定すると、並行する仕事が混ざる。

- 同日の同じエピソードは従来どおり同じファイルに追記する。翌日の続きなど、新しいファイルを作る時点で前回が分かる場合にリンクを付ける。セッション内では作成 CLI が返した実際のパスを使い、別セッションでは今回選んで読み直した activity を使える。
- 新規の話題、前回が不明な作業、複数の調査を対等にまとめた作業では省略できる。複数資料の参照には本文の通常リンクを使う。一件から二手に分かれた場合、各後続が同じ前回を指せる。
- 新しい側のファイルだけにリンクを保存する。前回を示す値は一か所とし、本文中の事例、比較対象、引用に含まれるリンクと区別する。セッション ID の取得は不要。

**記法案**は、本文末尾の専用の段落に Markdown の相対リンクを一つ置く方式。たとえば11月20日の記録から、同月19日の記録を次の形で参照する。

```markdown
前回の記録 → [activity-20261119aab](../20261119/activity-20261119aab.md)
```

CLI はこの書式の独立した段落を本文から読み、引用・コード例・通常の資料リンクを除く。新規保存時は末尾へ置くが、後から追記されて段落の位置が変わっても読めるようにする。二つ以上の指定や壊れた指定は曖昧な履歴として報告する。活動日ごとの編集、未保存分だけの記録、作成時の衝突回避、更新時の本文と SHA-256 の再取得は現在の保存手順を使う。リンク追加のためだけに既存記録を一括編集する必要はない。[activity の保存手順](../../skills/igapyon-miku-daybook/references/operations.md#add-an-activity)

## 2. 同梱する .mjs の操作案

| 操作 | 入力と結果 |
| --- | --- |
| `activity-history.mjs list` | `--date` または両端を含む `--from`・`--to`、任意の `--query`（タイトル・本文の文字列。URLも可）で絞る。日付・タイトル・リポジトリ相対パスを返す。新しい日から表示し、同日内の表示順は英字連番の長さと辞書順で固定する。 |
| `activity-history.mjs trace --path <activity> --depth 5` | 指定した一件から前回リンクを最大5本たどる。原案の既定は5本。0なら起点一件。取得結果は最も遠い祖先から起点までの順で返す。各件に日付・タイトル・パスを含め、エージェントが必要な本文を読めるようにする。 |
| `create-activity.mjs --previous <activity>` | 既存作成 CLI の任意引数。daybook ルート相対のパスを受け、前回のファイルと形式を確認して、新規 Markdown からの相対リンクを計算する。指定内容と下書きの既存リンクが一致すれば一つにまとめ、食い違えば作成前に理由を返す。 |

読み取り CLI は既存 CLI と同様に対象を `--repo-root` で指定でき、結果は JSON で返す。正規の新旧 activity 配置の列挙とパス検証には既存の共通処理を使う。日付の候補を絞ってから本文を読み、一覧には本文全体を載せない。旧配置の日次ファイルや短い接尾辞も対象とする。[record-paths.mjs](../../skills/igapyon-miku-daybook/assets/daybook/scripts/record-paths.mjs)

`trace` は辿ったパスと停止理由を返す。「前回の指定なし」は記録された鎖の先頭、「指定本数に到達」は今回の読み取り範囲の端として扱う。リンク切れ・循環・重複指定・リポジトリ外や activity 以外への指定では、それまでに読めた経路と問題箇所を返す。祖先の順序はリンクから決まり、ファイルの日付で並べ直す必要はない。旧記録で鎖が途切れたら、日付・話題で別途検索できる。検索で見つけた候補を自動で祖先に組み込まない。

後続を探す操作も同じ記法から導出できる。指定 activity を「前回」として指すファイルを検索すれば、二手に分かれた続きも表示できる。初版の優先は一覧・検索、前回リンクの作成、祖先取得とする。逆引き専用コマンドは過去の記録を起点に後続を探す利用頻度を見て判断する。

## 3. 履歴の確認と作業再開

「何をしていた？」なら、日付・話題から候補を探して経緯を説明する。「続きをやって」なら、選んだ記録の祖先を古い方から読み、試行・訂正・最新の結果と次の一手を確認してから再開する。同じ日・似た題名で複数の作業が残り、選択で実行内容が変わるときは、候補の違いを示して対象を確かめる。一日の連番には作業時刻や担当セッションの意味を持たせない。

再開範囲は今の依頼で指定できる。中断時点で次回の範囲を伝える必要があれば、activity 本文に「次回は旧形式の読み取りだけ確認する」のように一文を残す。作業結果や判断理由は普段どおり activity に書き、継続管理している仕事の現在の進捗や完了条件はその task を参照する。過去の予定を読むだけで実施済みと判断しない。

## 4. Waypoint 廃止の範囲

廃止するのは、専用ファイルの新規作成、番号付き親子の維持、`ready`・`in_use`・`closed` の遷移、再開後の閉鎖・整理という運用。代わりに利用者は activity への直接リンクと短い範囲指定を渡す。作業リポジトリへの参照は引き続き daybook 側に置く。

この変更で失うのは、**名前や番号を付けた引き継ぎ口を、作業履歴とは別に開閉し、再開可能・利用中と記録済み・終了という状態を一覧する機能**である。activity に後続があることから分かるのは「続きが記録された」ことまでで、未着手・完了は判定できない。今回の目的は履歴をたどった再開なので、同じ状態管理を activity に導入する必要はない。独立した複数の仕事の進捗管理が必要な場面では、既存の task や計画書がその役割を担える。

すでに渡してある waypoint のパスは引き続き開けるようにする。名指しで再開を頼まれたら、旧ファイルの範囲・リンク・最初の確認事項を読み、現在の依頼と記録に照らして続ける。古いファイルだけに残る引き継ぎ事項もここで拾う。再開後の経緯は通常の activity に保存する。旧ファイルは元の場所に残し、自動閉鎖や一括移行は行わない。従来の「waypoint を作って・閉じて」という依頼には、変更点を伝え、該当する activity のパスと再開範囲を案内する。

## 5. 採用判断に使う例

| 場面 | 成り立つべきこと |
| --- | --- |
| 19日に調査 A と実装 B が並行し、20日に別のエージェントが A を再開 | 19日の一覧には両方が出る。20日の A からたどると19日の A に戻れ、B は混ざらない。 |
| 二つのセッションが同じ A から新しい activity を作成 | 各作成結果は別パスになり、各ファイルのリンクは A を指す。A の編集は不要。 |
| A → B → C の順に作業し、C から深さ1を指定 | B、C の順に二件を返す。深さ2なら A、B、C を返す。 |
| 旧形式のリンクなし記録、壊れたリンク、循環を読む | 旧記録単独も正当な結果。欠損や循環は部分結果とともに識別できる。 |
| 番号付きの旧 waypoint で一部だけ引き継いでいる | 指定された子の範囲とリンクを読んで再開し、再開結果を activity に残せる。 |

採用時は先に activity の作成・読み取りを同梱 CLI から使えるようにし、この例で再開できることを確認する。その後、現在 waypoints の参照資料にある汎用の履歴検索・再開手順を activity の資料へ移し、スキル入口・関連 references・利用者向け README と配布版・DEVELOPMENT の案内を合わせる。本書は仕様検討段階の提案である。
