# Sol 向け実装計画

**到達点**は「11月20日の調査の続きを」と頼まれたエージェントが、日付と話題から記録を見つけ、同じ仕事の前回リンクをさかのぼり、指定された範囲を再開できること。まず同梱 CLI を完成させて隔離した daybook で動かし、その後に waypoint の運用を終了する。仕様と経緯は[仕様案](daybook-activity-history-and-waypoint-retirement.md)にある。

対象はこのリポジトリのスキルソース、同梱 CLI、テスト、配布検査、利用案内。確認時の HEAD は `12ce989`。Sol が着手するときは現在の Git 状態を読み、仕様案と本計画を引き継ぐ。実 daybook の記録移動・既存ファイルの一括編集、ユーザー用スキルへの同期、リリースは別作業とする。

## 初版の入出力

以下は実装担当者が同じ期待値でコードとテストを書けるようにするための設計値。CLI のパス引数はすべて daybook ルート相対、Markdown リンクだけは記録ファイルのディレクトリ相対とする。

| 操作 | 初版の契約 |
| --- | --- |
| `create-activity.mjs --previous PATH` | 既存引数に一つ追加する。実在する activity を確認し、本文末尾に仕様案の専用段落を入れてから既存の排他的作成で公開する。stdout は従来の `path` と `warnings`。 |
| `activity-history.mjs list [--date D] [--from D] [--to D] [--query TEXT]` | 日付指定なしは全期間。範囲は片端だけでもよく、両端を含む。`--date` と範囲の併用、逆転した範囲は引数エラー。文字列検索は大文字小文字を区別するリテラル部分一致でタイトルと本文を対象にする。結果は `{records:[{date,title,path}]}`、該当なしは空配列。日付降順、同日は接尾辞の長さ・辞書順の昇順。 |
| `activity-history.mjs trace --path PATH [--depth N]` | 深さはたどるリンクの本数。既定5、0は起点だけ。非負の安全な整数を受け付ける。結果は `{records:[{date,title,path}],stop:{reason,at}}`。読めた一件を一度だけ含め、祖先から起点の順で返す。 |

履歴 CLI は両操作で `--repo-root`、`--help` を提供する。通常結果は stdout に JSON を一つ出す。タイトルは本文の最初の H1、欠落時はファイル名の拡張子を除いた値。本文が必要なときは、返されたパスを読み取る。

`trace` の `at` は停止を判断した activity のパス。深さに達したらそこで `depth_limit` とし、さらに先のファイルを開かない。上限に達する前に前回指定がなければ `no_previous`。この二つは終了コード0。リンク切れは `missing_target`、循環は `cycle`、複数または不正な指定は `invalid_link`、リンク先本文の形式不正・読み取り失敗は `unreadable_target` として、それまでの `records` と停止理由を stdout に残し、終了コード1とする。問題のリンク先が分かる場合は `stop.target` にも入れる。起点自体が読めない場合や CLI 引数の誤りは stderr と非ゼロ終了。部分結果を「すべて読めた」と扱わずに済む。

## 実装手順

以下の `assets/daybook/scripts/` と `references/` は [igapyon-miku-daybook](../../skills/igapyon-miku-daybook/SKILL.md) 配下を指す。

### 1. 「前回の記録」を一度だけ解釈する

- `assets/daybook/scripts/activity-files.mjs` に、専用段落の読み取りと生成を追加する。作成と履歴取得から同じ処理を呼ぶ。現行の `readActivity`、`parseFrontMatter`、`record-paths.mjs` の検証を利用する。[保存処理](../../skills/igapyon-miku-daybook/assets/daybook/scripts/activity-files.mjs)
- 対象は front matter を外した本文の独立した段落。ラベルは対象ファイルの stem と一致させる。段落の後ろへの追記、CRLF、旧形式の接尾辞を扱う。通常のリンク、引用、インデントされたコード、バッククォート・チルダの fenced code 内の記法例を拾わない。本文全体への単純な部分一致検索はコード例を誤認する。
- リンク先の `../` は記録のディレクトリを基準に正規化してから検証する。新旧配置をまたぐ相対リンクを許し、外部 URL、絶対パス、ルート外、他の記録種別、symlink 経由は追跡エラーにする。CLI に渡すルート相対パスと Markdown の相対リンクは入口で区別する。[共通パス処理](../../skills/igapyon-miku-daybook/assets/daybook/scripts/record-paths.mjs)

### 2. 既存の作成 CLI に接続する

- `create-activity.mjs` の引数解析・help と `createActivity` を更新する。activity は採番が衝突しても同じ日の同じディレクトリに置くので、リンクは一時ファイルの書き出し前に計算できる。現在の排他的公開、再採番、標準入力とファイル入力の両経路を利用する。
- 指定先を検証し、下書きに同じ専用段落がすでに一つあればそのまま使う。異なる指定、複数指定、対象欠落は新しい記録の公開前にエラー。前回のファイルへの追記は不要。通常の `--previous` 省略呼び出しは従来どおり下書きを保存できる。日付・スレッド・最新ファイルから前回を補完しない。
- 既存 activity の通常更新には現在の本文と SHA-256 の照合を使う。モード切替・同日追記・Issue 取り込みが前回リンクを必要とする仕様へ広げない。activity helper を別ファイルへ分ける場合だけ、`operations.md` と `issue-import.md` の同梱必須ファイル一覧にも依存を反映する。

### 3. 一覧・祖先取得を Node.js CLI にする

- `assets/daybook/scripts/activity-history.mjs` を追加する。`list` は `listCanonicalRecordFiles(root, ["activity"])` と既存の重複 ID 検査を使う。新旧配置だけを調べ、日付で絞った後にタイトルと本文を読む。対象ファイルの読み取り失敗を「該当なし」として返さない。
- `trace` は指定パスから必要なリンクだけを順に読み、訪問済みパスで循環を検出する。たどった順を最後に反転する。日付、連番、本文の一般リンクを利用した祖先の推測は行わない。旧日次ファイルに複数の話題があれば、エージェントは返されたパスから本文を読み、依頼に該当する箇所を使う。
- 新 CLI の既定ルートと実行入口の判定は既存 CLI にそろえる。別ディレクトリで起動し、明示した `--repo-root` の記録を読む場合も扱う。Node.js と同梱物だけで動かす。後続の逆引きは将来候補とし、初版では専用コマンドや索引を追加しない。

### 4. 代替経路が配布物でも動くことを確認する

既存の `activity-files.test.mjs` に作成・保存の回帰ケース、新規 `activity-history.test.mjs` に下表の CLI 経由のケースを置く。リポジトリ直下の `scripts/check-daybook-runtime.mjs` の help 検査と隔離実行には、親と子の作成、一覧、旧配置を含む trace を追加する。別 cwd と別名パスからの起動も既存 fixture を利用できる。配布 ZIP の検査も同じ runtime checker を呼ぶ。新 CLI を `scripts/skill-reference-routes.mjs` の daybook 経路に登録し、対応する利用手順から参照できるようにする。[隔離実行](../../scripts/check-daybook-runtime.mjs)・[配布時の参照検査](../../scripts/skill-reference-routes.mjs)

| fixture／操作 | 受け入れ条件 |
| --- | --- |
| 旧配置の A、同じ日付の別件 X、A の続き B、B の続き C | 日付・範囲・日本語・URL で検索できる。C の深さ0は C、1は B/C、5は A/B/C。X が混ざらず、C より古い実施日を後から記録した例でもリンク順を優先する。 |
| 同じ日に無接尾辞・短い接尾辞・`zzz`・`aaaa`／新旧に同一 ID | 同日順が安定し、重複 ID はパスを示す。別の入力として、リンクなし旧記録は一件として読める。 |
| 同じ A から二つの作成プロセス／すでに専用段落のある下書き | 子は別々のパスで、ともに A を一回だけ参照。A のバイト列は不変。下書きと引数が矛盾すれば子を公開しない。 |
| 段落の後に追記／コード例と引用だけ／二重指定／リンク切れ・自己参照・二件の循環 | 正規の段落だけを選び、異常時は停止理由と有限な部分列を返す。深さ上限の先にある壊れたファイルを読まない。 |
| 他の種別・外部・symlink を指すリンク／一覧・trace の繰り返し | 指定外を読まない。読み取り CLI の前後で記録ツリーの内容が一致する。 |

この段階で、使い捨ての daybook に対し、Sol は「11月20日の調査を探す → 指定した履歴を読む → 調査の残りを特定する」を通す。読んだパス・順序・残件を記録する。ここまで通ってから通常の案内を切り替える。

### 5. 再開手順を activity に移し、waypoint 運用を終了する

1. `references/activity-capture.md` に履歴検索・再開の手順を置く。入口を選び `trace` の結果を古い順に読み、実施済み・訂正・未解決事項を確認する。履歴質問には説明で応じ、再開依頼では現在の対象範囲を確認して仕事を続ける。同日で候補を区別できないときは候補の違いだけを尋ねる。記録禁止・ファイル指定・既存の保存モードを尊重する。
2. `SKILL.md`、`references/operations.md`、`records.md`、`todos.md`、`topics.md` の振り分け、配置図、再開・完了時の案内を更新する。作業先リポジトリへの一方向参照と、task がある場合の進捗更新を引き継ぐ。通常の再開で旧 waypoint 群を走査する手順は終了する。
3. `references/waypoints.md` は従来パスを受け取るための短い互換案内にする。過去の設計文書から参照する節は、新しい手順へ辿れるよう必要な見出し・アンカーを残す。旧ファイルを名指しされたときは、そこだけにある対象範囲・参照先・最初の確認事項を読み、指定された子があればその子の範囲だけを再開する。旧ファイルに activity リンクがなくても task・計画・本文の情報を使える。新規作成、親子の保守、状態更新、自動閉鎖・整理を通常操作から外す。既存の waypoint ファイルは現在の場所で読める。
4. 旧操作を頼まれた場合の案内を定める。「作って」は適切な activity と次回の範囲を案内し、「閉じて」は専用の閉鎖操作が終了したことを説明する。旧状態を activity や task の完了判定へ転記しない。ルートと `src/assembly/` の README、`DEVELOPMENT.md` の例を合わせる。

**最終受け入れ例**。番号付きの旧 waypoint に「調査だけを再開」、親に別の仕事を書く。指定した子から再開でき、作業の結果が activity に残り、旧ファイルの内容・状態はそのままであることを確認する。さらに「何をしていた？」と「その続きを」の二つを読み合わせ、前者が過去の指示を実行しないことを確かめる。CLI の実行結果、指示文の読み合わせ、モデルで実際に確認した事例は区別して報告する。

### 自己レビュー後の修正

- 前回リンクを探すときに、HTML コメントや `<pre>` などのブロックを読み飛ばし、見出しや読み飛ばしたブロックの境界を判定に使うようにした。リンクが通常本文の段落内に出てきた場合は無視する。コメント内のリンクと、見出しの直前にある有効なリンクの再現ケースを回帰テストに追加した。
- activity の一覧は年・月・日付で探索対象を絞ってからパスを検証する。旧配置では月内のファイル名の日付で絞る。範囲内の配置ミスやリンク先の異常が報告されることと、年・月をまたぐ26通りの日付指定が全件一覧を後から絞った結果と一致することを確認した。
- 修正後は daybook の106件、配布・参照の78件、スキル形式検査、再生成した配布 ZIP の検査が通過した。

### 再レビュー後の修正

- 箇条書きや引用が前回リンクの直後に空行なしで続く場合も、前回リンクを独立した段落として認識するようにした。下書きにある前回と `--previous` が食い違えば公開前に拒否し、一致すればリンクが一つのまま保存されることを CLI で確認した。
- 修正後の自己レビューでは、区切り線が直後に来る場合も判定に加えた。段落を継続する記述や、リンク行を見出しに変えるハイフンの下線を区別する。隔離環境で作成、ハッシュ照合付きの追記、履歴取得、矛盾する作成の拒否を通して確認した。
- daybook の108件、配布・参照の78件、最終差分から再生成した配布 ZIP の検査が通過した。

### 前回リンク直前のブロック境界

- 下線式の見出しや区切り線の直後に空行なしで前回リンクが現れる場合も、独立した段落として扱う。下線式のレベル1見出しを一覧・履歴のタイトルにも使う。引用やリストの続き、見出し本文のない等号行を境界と誤認しないことと、矛盾した `--previous` でファイルが作られないことをテストした。
- 自己レビューでは26通りの短い Markdown をローカルの Mistune と比較し、前回リンクが独立した段落かどうかの判定が一致した。daybook の109件、配布・参照の78件、再生成した配布 ZIP の検査が通過した。
