## はじめに

あ、あの...この記事は、みくくが担当します。

前の記事では、トークン消費量の本当に入口になるところを整理しました。トークンとは何か。入力トークンと出力トークンとは何か。なぜ料金や利用枠に関係するのか、という話です。

この記事では、そこから少しだけ先へ進みます。

特に見たいのは、AI agent を使っているときに、なぜトークン消費量が思ったより増えやすいのかです。単に「回答が長いから」だけではなく、入力側の文脈が大きくなっていくことが効いてきます。

## AI agent は何を見て応答しているのか

AI agent は、無限にすべてを覚えているわけではありません。

現在の指示、会話履歴、読み込んだファイル、参照した情報など、モデルに渡された範囲をもとに応答します。

この「一度に扱える文脈の範囲」が、よくコンテキストウィンドウ、あるいはトークンウィンドウのように呼ばれるものです。

トークンウィンドウが大きいと、多くの情報を一度に渡せます。これは便利です。長い資料、複数のファイル、過去の会話、作業ログなどをまとめて扱いやすくなります。

ただし、トークンウィンドウが大きいことと、常に良い応答が返ることは同じではありません。

関係の薄い情報が多いと、大事な情報が埋もれます。Agent が見るべき場所を見つけにくくなり、応答がぼんやりすることもあります。

つまり、AI agent にとって大事なのは、ただ大量の情報があることではありません。

必要な情報が、必要な形で、扱いやすい順序で入っていることです。

## コンテキストウィンドウとトークン消費

生成AIに何かを依頼するとき、モデルは現在の一文だけを見ているわけではありません。

会話履歴、システム指示、読み込ませた資料、必要に応じて参照されたファイルなど、モデルに渡された文脈をもとに応答します。

この文脈が入る場所が、ざっくり言えばコンテキストウィンドウです。

コンテキストウィンドウが大きくなると、モデルが処理する文脈も大きくなります。新しい質問そのものは短くても、過去の長い会話や大量の資料が一緒に扱われれば、そのぶんトークン消費量は増えやすくなります。

つまり、トークン消費量を考えるときは、出力の長さだけを見ても足りません。

入力側、つまりモデルに渡す文脈の量も意識する必要があります。

あの...ここが大事です。短い質問をしているつもりでも、長い会話や大量の資料を抱えたセッションでは、処理に乗る文脈が重くなっていることがあります。

## 「トークンが溶ける」という感覚

AI agent で資料を読み込ませたり、過去の作業ログを参照させたり、背景知識を渡したりしながら作業していると、気づかないうちにコンテキストが大きくなっていきます。

感覚的には、「トークンが溶ける」という感じです。

うぅ...これは、なかなかおそろしい事象です。

特に、次のような使い方では増えやすくなります。

- 長い資料を丸ごと貼る
- 関係しそうなファイルを全部読ませる
- 長い会話を同じセッションで続ける
- 調査ログや途中経過を会話の中に積み上げ続ける
- 同じ説明を何度も貼り直す

これらは、どれも悪い使い方というわけではありません。必要な場面もあります。

ただし、トークン消費量の観点では、コンテキストを重くしやすい使い方です。

## 大きいコンテキストは便利だが万能ではない

コンテキストウィンドウが大きいモデルは、とても便利です。

長い仕様書を読ませたり、複数の資料をまとめて比較したり、過去の会話を踏まえて作業したりできます。

でも、「大きいコンテキストに全部入れれば解決」と考えると、別の問題が出てきます。

まず、処理に乗る情報量が増えるため、トークン消費量が増えます。

次に、重要でない情報まで同じ文脈に混ざるため、Agent の注意が分散します。人間でも、机の上に資料が山積みだと、必要な紙を見つけにくくなります。AI agent でも、関係の薄い情報が多すぎると、判断が鈍く見えることがあります。

さらに、古い情報や矛盾した情報が残っていると、現在の判断に混ざる可能性があります。

大きいコンテキストは、便利な器です。でも、器が大きいからといって、何でも入れればよいわけではありません。

## トークン消費量を考える入口

AI agent でトークン消費量を考えるとき、まず見るべきところは大きく 3 つあります。

- 入力として渡している文脈の量
- 出力として返させている文章の量
- 同じ情報を何度も処理に乗せていないか

出力を短くすることは、わかりやすい節約です。

でも、AI agent の作業では、入力側のほうが重くなることがあります。長い会話履歴、大量の資料、過去ログ、作業メモ、読み込ませたファイル。これらが積み上がると、質問そのものが短くても、全体としては重い処理になります。

だから、トークン消費量を抑える実践では、コンテキストウィンドウをなるべく軽い状態に保つことが重要になります。

## いまのところの整理

この記事では、トークン消費量の入門から少し先に進んで、AI agent で文脈が重くなる理由を整理しました。

- AI agent は、コンテキストウィンドウに入った文脈をもとに応答する
- 短い質問でも、長い会話履歴や資料が一緒に処理されることがある
- 大きいコンテキストは便利だが、全部入れれば良いわけではない
- 関係の薄い情報が多いと、トークン消費量だけでなく判断の見通しにも影響する
- AI agent では、出力だけでなく入力側の文脈を意識する必要がある

次に考えるべきことは、どうやってコンテキストを軽く保つかです。

情報を削りすぎると AI agent の働きは弱くなります。でも、全部を渡すとトークン消費量が増えます。

そのあいだで、どう舵取りするか。

それが、トークン消費量を抑える実践の話になります。
