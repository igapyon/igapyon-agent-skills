# Generated Artifact Review

Use this reference to review whether generated artifacts are correctly updated,
intentionally tracked, and safe to commit or release.

This review is important for miku-soft and nearby repositories because they may
include single-file HTML, generated JavaScript, `index.json`, `dist/`, bundles,
jars, zips, generated docs, release staging directories, and skill packages.

## Review Priority

Use this review before commit, handoff, software completion, release readiness,
or package publication when generated files are present or expected.

## Core Checks

Check whether:

- generated artifacts required by the repository are updated after source
  changes
- generated artifacts that should not be committed are ignored or kept local
- generated files are distinguishable from source files
- README, CONTRIBUTING, or architecture docs explain which files are generated
- generation commands are documented and still work
- generated indexes such as `index.json` are regenerated when references,
  skills, assets, or docs change
- single-file HTML, bundled `.mjs`, jars, zips, and release assets are built
  from current source
- generated artifacts do not contain placeholders, local absolute paths,
  secrets, timestamps that should be deterministic, or stale version strings
- release staging directories do not contain stale artifacts from previous
  builds

## miku-soft Artifact Checks

For miku-soft style repositories, pay special attention to:

- source HTML versus generated single-file HTML
- source TypeScript or JavaScript versus generated runtime files
- Agent Skill bundles and bundle zips
- `index.json` generated by `miku-indexgen`
- Java jars, Maven plugin packages, and distribution zips
- `dist/`, `bundle/`, `target/`, `workplace/`, and release staging folders
- generated docs or article indexes

Flag issues when source changes require generated files to be refreshed, or
when generated files are refreshed but the source of truth is not updated.

## Agent Skill Generated Index Checks

For igapyon-managed Agent Skills, use
[agent-skill-review.md](../agent-skill/agent-skill-review.md) for the full Agent Skill review.
In this generated-artifact review, check only the generated-file aspect:

- `index.json` was regenerated after adding, removing, or renaming references,
  assets, helper files, or other bundled skill files
- `miku-indexgen` or equivalent index generation is configured to scan the
  intended locations and file types
- generated `index.json` does not contain local paths, placeholders, stale
  entries, or unrelated files
- generated `index.json` contains meaningful discovery information, not only a
  formally valid but low-signal file list
- generated `index.json` is included when the skill is bundled or installed

## Commit and Release Checks

Before commit or release, check:

- expected generated files are included in the diff
- unexpected generated files are not included
- generated files are reproducible enough for review
- artifact filenames include product and version when appropriate
- release assets are built cleanly from the intended source or tag
- artifact contents checks or smoke checks exist for important bundles
- generated artifacts do not include `node_modules`, local caches, logs,
  `.DS_Store`, `workplace/`, or temporary files

## Severity Guidance

Use these severity levels:

- High: release or runtime artifact is stale, missing, or built from the wrong
  source.
- High: generated artifact includes secrets, local paths, private files, or
  unintended workspace contents.
- Medium: source changed but required generated files or indexes were not
  regenerated.
- Medium: Agent Skill `index.json` is stale after reference, asset, or helper
  file changes.
- Medium: generated files are committed without clear source-of-truth or
  regeneration rules.
- Medium: release staging can pick up stale artifacts from previous builds.
- Low: minor generated-file naming, ordering, timestamp, or documentation issue
  makes review harder but does not change behavior.

## Review Output

Use this format when generated artifacts are in scope:

```text
Generated Artifact Review

Generated state: current / stale / mixed / not checked
Commit suitability: suitable / risky / unclear
Release suitability: suitable / risky / not applicable

Findings:
- Severity: ...
  Issue: ...
  Why it matters: ...
  Suggested direction: ...
```

Do not regenerate, delete, stage, or ignore files during review mode unless the
user explicitly asks to switch to maintenance work.
