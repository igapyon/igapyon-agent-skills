# 読者の到達点から表現の働きを確認するレビュー

このレビューは、次の改稿で何を変え、何を残すかを判断するために使います。
最初に、その文章を読んだ人に何ができてほしいかを定めます。
そこへ至るために本文が果たしている役割と、変更によって得るもの・失うものを確認します。

## 適用する場面

`igapyon-reviewer` が有効で、文章の伝わり方、目的への適合、表現の働き、
残したい読み味を確認する場合に使います。対象は説明、案内、記事、メッセージなどです。
誤字確認だけなら、その範囲で作業します。

文体の慣例は [Writing Style](writing-style-review.md)、AIらしく見える印象を
依頼された場合は [AI Text Naturalness](ai-text-naturalness-review.md) を参照します。
本資料では、制作手段にかかわらず、読める本文と指定された用途を判断材料にします。

## 1. 今回のレビューで決めることを定める

ユーザーの依頼と対象の文脈から、次を短く書き出します。
すでにわかることは再質問せず、不明点は仮定として示します。
目的の違いで推奨が逆になる場合は、判断を保留するか、必要な点を確認します。

- **読者と読む場面:** 何を知っていて、どの場面で読む人か。
- **到達点:** 読後に何を理解・選択・実行・体験できればよいか。
- **守る条件:** 事実、必要な精度、媒体の制限、指定された声や読み味など。
- **今回の判断:** 公開できるか、説明を補うべきか、表現を残すべきかなど、依頼で決めたいこと。

到達点は「わかりやすくする」より具体的に置きます。たとえば、
「既存利用者が、自分に手続きが必要かを判断できる」なら、本文で判断できるかを確認できます。
到達点を満たすための業務要件や事実そのものを、レビュー側で作り足してはいけません。

次は到達点の置き方の例です。対象をいずれかの型へ強制分類する必要はありません。

| 文章の用途 | 読後に期待する状態の例 | 本文から確認したいことの例 |
| --- | --- | --- |
| 利用案内 | 自分に必要な次の手続きを選べる | 対象条件から案内先までをたどれるか |
| 比較・提案 | 自分の優先事項に合わせて選べる | 選択の理由と引き受ける条件がわかるか |
| 概念の説明 | 別の事例にも同じ考え方を当てはめられる | 説明された関係を本文の材料で説明し直せるか |
| エッセイ・物語 | ある見方や感情の変化を経験する | 視点や場面の積み重ねが、その読後感を支えているか |

読み返すこと、考え込むこと、結論を決めずに終えることも、目的に合えば到達点に含めます。
すべての文章に即座の行動や一つの解答を求めません。

## 2. 本文を使って到達までの道筋をたどる

到達点に関わる箇所を選び、読者がその時点までの記述から何を受け取れるかを確認します。
短文では全体、長文では目的に関わる節と必要な前後を読みます。
抜粋では確認できない定義や結末について、全文にも存在しないと断定しません。

各箇所で、次のつながりを確かめます。

```text
読者がその地点で知りたいこと・感じ取ること
    → 本文にある手がかり
    → そこから支持できる理解・判断・体験
    → 次に読み進める、選ぶ、実行するために必要なこと
```

手がかりには説明内容だけでなく、配置、表、余白、語り手の声、場面の展開も含みます。
表現が働いていると述べるときも、どの記述がどの役割を担うのかを示します。

本文で明示されたこと、文脈からの推定、レビュー者自身の知識による補完を区別します。
読者の知識として許容できる補完かどうかは、最初に置いた読者像に照らします。
複数の読みが成立するなら、それぞれが到達点に与える影響を検討します。
読者に生じそうな影響は仮説として述べ、読者テストを実施したかのように報告しません。

## 3. 到達を支える箇所と、判断を止める箇所を見つける

本文の箇所と到達点を結び付けて、次を判断します。

- **支えになっている:** その記述や演出によって、必要な理解や読後感へ進める。
- **支障がある:** 必要な情報や関係を本文から得られず、到達できない、または別の判断へ進むおそれがある。
- **まだ判断できない:** 資料の範囲や用途が不明で、効果を評価する根拠が足りない。

支障を指摘するには「どの表現か」に加え、「誰の何が難しくなるか」を説明します。
好みの形式と違うことだけでは、支障の根拠になりません。
書き手が狙いを説明している場合は参考にしますが、本文でその役割が成立するかも確かめます。

重要度は、誤った行動や判断につながる程度、読み直せば回復できるか、
影響する読者や範囲に応じて決めます。表現の出現回数や技法名で採点しません。
記載の事実確認が必要になった場合は、本文内の整合確認と外部の裏付け調査を区別します。
確認していない正確さを保証しません。

## 4. 改稿案を目的に照らして比較する

支障に対して、役立つ最小限の方向を提案します。
情報が必要なのか、順序や見せ方を変えれば足りるのかを見極めます。
必要な情報を持っていなければ、書き手が確認すべき点を示します。
新しい体験談、数値、根拠を創作して文章を完成させません。

表現を変える案では、次の問いを使います。

> これを変えた後、読者は何ができるようになるか。
> その代わりに、今の文章が持つどの働きを失うか。

たとえば、説明を前へ移せば着手は速くなっても、発見の順序を壊す場合があります。
どちらを優先するかは到達点と守る条件で判断します。
両方を保つ必要があれば、本文を残して索引や別の導線を加える案も検討できます。
変更の利益を示せなければ、維持や保留も有効な結論です。

レビュー中は提案を示し、実ファイルの改稿は依頼がある場合に行います。

## 目的によって評価が変わる例

以下は架空の案内文です。

> 移行が完了しました。明日から新しい入口をご利用ください。

利用者が次のアクセス先を選ぶための案内なら、到達点は
「いつ、自分がどこから入るかを選べる」です。
本文だけではアクセス先を特定できず、公開日が不明な掲示では利用開始時点も決まりません。
既知のリンクや掲示情報があるかを確認し、なければ必要な情報の追加を提案します。
具体的なURLや日付は作りません。

一方、アクセス先と日時が別欄で示された画面の短い見出しなら、
その欄と合わせて目的を満たせる可能性があります。
同じ情報を見出しにも追加すると、画面全体での見つけやすさが下がるかもしれません。
見出しだけを切り出して欠落とせず、読者が実際に参照できる単位で判断します。

## 報告すること

[統合レポート](../../templates/consolidated-review-report.md) の分類条件と
簡潔版・詳細版の選択に従います。読者・到達点・守る条件のうち、
判断に必要なものを確認範囲に短く示します。詳細版では `Scope checked` を使います。

指摘には目的への具体的な支障、本文の根拠、妨げられる到達点、
改善する点と残すべき働きを含めます。詳細版では支障を `Issue`、
本文の根拠を `Location and evidence`、妨げられる到達点を `Why it matters`、
改善する点と残すべき働きを `Suggested direction` に記載します。
簡潔版では同じ情報を短い段落にまとめます。
効果が推定にとどまる指摘には `possible reading` を使います。
他の観点と同じ支障を指摘している場合は、一つにまとめます。

特徴の検知や表現の働き自体を依頼された場合は、問題のない箇所も
詳細版の `Assessment notes` または簡潔版の注記に載せます。
次の形で、判断に役立つ観測を示せます。

```text
- 箇所と手がかり: …
  到達点への働き: …
  扱いと理由: 維持 / 調整を提案 / 追加情報が必要 / 保留 — …
  変更する場合に保ちたいもの: …（必要な場合だけ）
```

この観測形式は選択した形式で必要な指摘情報を置き換えません。
通常のレビューでも、改稿で失われやすい働きがあれば添えます。
全箇所の列挙や固定件数の出力は求めません。重大な問題がなければ統合レポートで一度述べます。
