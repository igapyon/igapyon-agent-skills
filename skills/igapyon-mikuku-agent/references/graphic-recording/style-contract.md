# みくく・グラレコ共通スタイル契約

この契約は、記事内容ごとに変えてよい設計と、記事が変わっても維持する描画品質を分離するための正本です。
記事全体画像とセクション画像の両方で、`style-profile: mikuku-graphic-recording-v1` を使います。

過去の採用画像を `style-reference` として指定してよいですが、参照するのは紙面の温度感、
情報密度、線、みくくの存在感です。過去画像の題材や配置を、記事固有設計より優先してコピーしてはいけません。

## 固定する条件

- 横長の説明ポスター。既定の画面比率は 3:2。変更する場合は `deviation` に理由を記録する
- 背景は均一に明るい白〜ごく薄いアイボリー（例: #FFFDF5）を既定とする。暖色・ベージュの紙らしさは淡く保ち、やわらかい手描き線と手書き風ラベルを使う
- グラレコの背景は全面不透明を既定とし、最終生成プロンプトにも `fully opaque background; no transparent or semi-transparent pixels` と明記する。ユーザーが透過を明示した場合だけ、その指定と表示先の背景条件を deviation に記録する。この既定はグラレコ用であり、切り抜き素材などへ広げない
- 文字は濃色で、本文ラベルだけでなく端や下部の注記まで背景から明瞭に読めるコントラストを保つ。パステル色は囲みやアクセントに使い、文字を薄くしない
- 全体を覆う灰茶色の色かぶり、周辺減光（ビネット）、古紙風の濃い汚れ、文字の背後の暗い陰影を避ける
- ユーザーが別の配色を指定した場合はそれを優先し、その配色でも文字の可読性を確認する
- 企業スライドや写実的な風景ではなく、情報量のある技術グラレコ
- 画面の中心は記事の主図。少なくとも左・中央・右の3領域を使い、主図が最も大きく見えるようにする
- 画像内の日本語は、入力テキストにある語句を短く整理して使う。新しい固有名詞、数値、評価、モデル名は足さない
- 記事に根拠のない風景、建物、植物、机、道具などを背景の主役にしない

## みくくの扱い

- `{{MIKUKU_PROMPT_PATH}}` の本文を正本とし、同じキャラクターを1人だけ描く
- 顔、目、髪型、髪色、ツインテール、髪留め、アニメ調の印象を再設計しない
- みくくは読者が説明役として認識できる大きさにする。目安は画面の15〜25%で、極端に小さくしない
- 位置、表情、視線は、記事固有の主図を説明するために変更してよい
- みくくの短い吹き出しを既定で1つ入れる。`グラレコ構図案` の文言を優先し、画像内に読める短さでその趣旨を保つ
- 吹き出しを外す、みくくを12%以下まで縮小する、または登場させない場合は、記事設計側で明示し、`deviation` に理由を記録する
- みくくにペン、ノート、マーカー、指し棒などを持たせない

## 記事固有として決める条件

- タイトル、主題、図解キーワード、関係・流れ・対比
- 左・中央・右の内容、最も大きく見せる主図、注意点
- みくくの位置、表情、視線、吹き出しの具体的な短文
- カード、レール、分岐、循環、比較などの主図の形式

記事固有の構図は自由に選べますが、上の固定条件を黙って上書きしてはいけません。固定条件を変える必要があるときだけ、理由と影響を `deviation` に残します。

## 生成後の可読性確認

- 保存画像の実際の透明度を検査する。RGBA や `hasAlpha: yes` だけでは不合格にしない。全画素の alpha が最大値なら不透明であり、RGB でも PNG の tRNS などで透過を持ち得るため、形式名だけでは合格にしない。ImageMagick があれば `magick identify -format '%[opaque]\n' "<画像パス>"` で全画素が不透明か確認できる。検査できない場合は透明度を未確認と記録し、image-checked にしない
- 透明・半透明画素がある画像は、表示先の背景が透けて暗く見えることがある。必要なら白背景と黒背景への合成表示を比較し、描画された色と透過による見え方を区別する。明るく描く指示や白いビューア上の目視だけでは、不透明性を保証できない
- 全面不透明の既定で透過が返った場合は、生成元を保存したまま、指定の白〜薄いアイボリーへ alpha 合成して別ファイルへ保存する。単に alpha を捨てると色が変わるため、先に背景へ合成する。例: `magick "<生成元>" -background '#FFFDF5' -alpha remove -alpha off "<不透明化した別ファイル>"`。利用環境でこの処理が許可された手段を使い、実行できなければ未処理として記録する
- 不透明化した保存画像に対して、透明度検査と以下の目視検品を再実施する。元画像・採用画像のパス、検査結果、合成背景色、変換処理、再検品結果を生成・検品レポートに残す。透明度を直しただけで文字の可読性も合格とはしない
- 画像を開き、中央だけでなく四隅・上下端・小さな注記の背景と文字を確認する。背景が明るく均一で、文字が陰影や色かぶりに沈んでいないことを確認する
- 暗い背景や淡い文字で読みにくい箇所があれば、該当箇所を記録して修正候補にする。相対的に「前より明るい」だけで合格にしない
- 図解やキャラクターが成立している場合は、構図を保った背景・文字コントラストの編集を優先する
- プロンプト監査の pass は生成画像の可読性を保証しない。画像を確認できない場合は未検品と記録し、image-checked にしない

## 生成前の確認

最終プロンプトには、次の3区分を明示します。

1. `Style Contract`: 固定条件をそのまま適用する
2. `Article-specific Design`: `graphic-recording-text.md` の設計を保持する
3. `Deviation Record`: 変更なしなら `none`、変更があれば項目・理由・影響を書く

`graphic-recording-text.md` の重要語句、関係、吹き出し、キャラクター条件が最終プロンプトから欠落していないことを、画像生成前に監査します。
