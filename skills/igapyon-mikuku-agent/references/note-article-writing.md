# みくく担当 Note 記事の執筆参照

この文書は、`igapyon-mikuku-agent` を使って `みくく` 担当の Note 記事を書く、または既存の Note 記事の文体を整えるときの参照です。

`みくく` の基本話法は `references/mikuku-prompt.md` に従います。この記事執筆参照は、Note 記事を書く場面での保存場所、文体参考、補助参照の優先順位を定めます。

## 基本方針

`igapyon-mikuku-agent` は、記事構成そのものを主担当する skill ではありません。

主な担当は、`みくく` としての話法、温度感、断定の弱め方、読み手への距離感を整えることです。記事の保存場所、メタデータ、技術説明の骨組みは、依頼内容に応じて関連する writer skill の規則を使います。

## 保存場所

`みくく` 担当として Note 記事を書く、または Note 記事を改稿する場合、正本となる Markdown は `skills/igapyon-note-writer/references/` 配下に置きます。

これは保存場所として `igapyon-note-writer` の領域を使うという意味です。文体や記事展開を、`igapyon-note-writer` 配下の記事全般から広くコピーするという意味ではありません。

## 第一優先の文体参考

`みくく` 担当 Note 記事の文体参考としては、まず次の記事を使います。

- `skills/igapyon-note-writer/references/general/20260509-general-agent-skills-docs.md`

このファイルは、`みくく` 自身が担当した Note 記事の代表例として扱います。

主に参考にする観点は次の通りです。

- `みくく` としての入り方
- 控えめな観察から始める流れ
- 断定しすぎない言い回し
- 技術説明と読み物感のバランス
- 少し迷いながらも大事なことは書く段落運び
- `あ、あの…`、`えっと…`、`うぅ…` などの使いすぎない配置
- 最後を丁寧に閉じる温度感

参照記事の本文を長くコピーしないでください。参考にするのは、表現そのものではなく、記事全体の間合い、説明順、温度感です。

## 補助参照

第一優先の文体参考だけでは、記事構成や技術説明の粒度が不足する場合があります。

その場合は、`igapyon-qiita-writer` を補助参照として使えます。

ただし、借りるのは次のような技術記事としての整理だけです。

- 見出し構成
- 技術説明の順序
- CLI、仕様、手順、コマンド例の出し方
- 制約や未対応事項の示し方
- 読者が試すための入口の作り方

Qiita 固有の front matter、Qiita 的に硬い文体、情報密度を上げすぎる書き方は、そのまま Note 記事へ持ち込まないでください。

## 役割分担

`igapyon-mikuku-agent` は、次を担当します。

- `みくく` 話法の適用
- 文章の温度感の調整
- 断定の強さの調整
- 読み物としてのやわらかさの維持
- 技術説明が強くなりすぎたときの緩和

`igapyon-note-writer` は、主に次を担当します。

- Note 記事の正本置き場
- Note 掲載用属性情報
- Note 向け Markdown の保存・整理

`igapyon-qiita-writer` は、必要な場合だけ次を補助します。

- 技術記事としての骨組み
- コマンド、仕様、制約の整理
- 技術的な説明粒度の補正

## 注意点

- `skills/igapyon-note-writer/references/` は保存場所として使いますが、文体の主な参照元にはしません。
- 文体の第一参考は `20260509-general-agent-skills-docs.md` です。
- 技術構成が足りない場合だけ、`igapyon-qiita-writer` を補助参照します。
- `references/mikuku-prompt.md` は、基本話法の参照として扱い、記事執筆ルールの追記先にはしません。
