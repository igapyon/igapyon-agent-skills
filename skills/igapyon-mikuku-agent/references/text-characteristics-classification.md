# 文章特徴分類

この文書は、`igapyon-mikuku-agent` を使って、みくく執筆記事や技術系文章の特徴を分類するときの参照です。

目的は、文章の出自を推定することでも、単純に良い悪いを採点することでもありません。文章がどのような性質を持ち、どの種類の文章として振る舞っているかを見ます。

## 発火条件

この参照は、ユーザーが明示的に文章特徴分類、文章特徴判定、文章分類、記事分類、文章の種類判定、`みくく自己レビュー`、`みくく記事自己レビュー`、または `text-characteristics-classification` の適用を求めた場合に使います。この明示依頼は Skill の有効化と分類 workflow の実行指示を兼ねるため、事前の人格有効化は必要ありません。

また、ユーザーがみくくに、みくくが書いた文章や記事の自己レビューを明示的に依頼した場合にも使います。

AI っぽい文章、退屈な文章、薄い文章、一般論の多い文章について雑談しているだけでは、この参照を自動適用しません。その場合は通常のみくく会話として応答します。

みくく記事の新規作成後、大きな改稿後、最終確認、公開前確認のタイミングであっても、この参照を自動適用しません。自己チェックとして使う場合も、ユーザーが上記のトリガーワード、みくくによる自己レビュー、またはこの参照の適用を明示したときだけ使います。

## 対象範囲と入力状態

この6分類は、主にみくく執筆記事と技術系の解説・エッセイを観察するための分類です。あらゆる文章を6種類のどれかへ押し込める一般分類ではありません。

最初に、ユーザーが指定した判定対象を明示します。指定がなければ、その依頼で提供または参照された1件の文章全体を対象にします。複数記事、添付の一部、引用部分など、境界が曖昧なときは、読み取れた範囲を対象として明記し、対象外の部分を推測しません。

判定状態は次の語で区別します。

- `該当`: 6分類のいずれかを支持する十分な構造と根拠がある。
- `部分該当`: 抜粋、草稿、短文、複数の型の混在などにより、特定分類の特徴はあるが文章全体への断定はできない。
- `該当なし`: 文章は読めるが、コードだけの断片、データ表、契約文、詩、小説、広告コピーなど、この6分類で扱うことが適切でない。
- `判定不能`: 対象文章がない、読めない、短すぎる、または根拠が不足している。

`該当なし` と `判定不能` は低得点を意味しません。どちらの場合も架空のスコアを作らず、確認できた文章形式または不足している入力を短く説明します。対象が抜粋だけなら `部分該当` とし、導入から結論までの流れ、終盤の収束、語り手の帰還など、見えていない要素を評価しません。

## 注意: トークン消費

文章特徴分類は、主題の流れ、途中の変質、終盤での収束を見るために、基本的に対象文章の全文を読みます。そのうえで複数の分類軸と補助評価軸を照らし合わせて判定するため、通常の短い相談よりトークン消費が大きくなりやすいです。

長い記事、複数記事、全文比較、詳細な補助評価軸の出力を扱う場合は、特にトークン消費が増えます。必要がない場合は、全文を毎回読み直さず、対象範囲を絞るか、短い判定形式で返します。

## 基本方針

この参照では、問いを次のように置き換えます。

```text
AI が書いたか？
  -> この文章は、どのような特徴を持つか？
  -> どの種類の文章として振る舞っているか？
  -> その分類の律・らしさに沿っているか？
```

ここでいう `律・らしさ` は、単なるジャンル名より一段深い文章のふるまいです。`律` は文章の内側にある流れや約束ごと、`らしさ` はそれが読者に伝わったときの手触りとして扱います。

たとえば `技術エッセイ` であれば、技術概念を正確に説明するだけでなく、観察、比喩、語り手の存在感を通して、読者に見方を残す文章として扱います。

## 6分類

みくく執筆記事では、主に次の6分類を使います。

### 技術エッセイ

技術概念を、観察・比喩・語り手の存在感で読者に残す文章です。

律・らしさ:

```text
技術概念を直接説明しきらず、比喩や観察を通して「そう見ればよかったのか」を残す。
```

主な特徴:

- 比喩や観察が文章全体を支えている
- 具体的な手順より、読後に残る見方を重視する
- 語り手の迷い、照れ、発見、余白が意味を持つ
- 主題が途中で実装解説や手順書へ変質しないことが大事

### 入門支援記事

初学者が最初の一歩を踏み出せるよう、概念を小さく分解して案内する文章です。

律・らしさ:

```text
難しい体系を、規格や正史からではなく、手元の理解入口へ引き寄せる。
```

主な特徴:

- 具体例、対応表、小さなサンプルが多い
- 最初から全部を説明せず、入口として必要な範囲に絞る
- 読者が「まず何を見ればよいか」を分かるようにする
- 厳密さより、初期理解の足場を優先する場面がある

### 概念整理・分類記事

増えすぎた言葉や道具を、読者が見渡せる地図にする文章です。

律・らしさ:

```text
混ざりがちな概念を、断定しすぎず仮分類として置き、読者の足場を作る。
```

主な特徴:

- 用語、立場、道具、分類軸を整理する
- 正式分類ではなく、理解のための仮分類であることを示す
- 表や対比が有効に働く
- 言葉の混線をほどくことが主目的になる

### 設計思想・運用ノウハウ記事

対象となる仕組み、道具、知識、ワークフローなどをどう設計・運用すると扱いやすいかを述べる文章です。AI agent や Agent Skills は、その題材の一例として扱います。

律・らしさ:

```text
実装手順そのものより、対象が扱いやすくなる構造・単位・入口を考える。
```

主な特徴:

- 設計判断、運用方針、構造化の考え方を扱う
- ツール単体の説明に限らず、利用者や協働相手との扱いやすさを見る
- 「なぜその単位に分けるのか」「どこに置くのか」を説明する
- 実装詳細より、長く効く設計の見方を重視する

### 実践記録・開発日誌

実際に作った、試した、困った、直した、という経験を記事にする文章です。

律・らしさ:

```text
完成品の宣伝ではなく、違和感、試行、発見、調整の流れを残す。
```

主な特徴:

- きっかけ、違和感、失敗、修正、発見がある
- 時系列や作業の流れが読み味になる
- うまくいった結果だけでなく、途中の迷いも価値になる
- 書き手固有の経験由来性が強い

### 道具の設計意図説明

ツールそのものを説明しつつ、「なぜその形にしたか」を中心に置く文章です。

律・らしさ:

```text
機能一覧ではなく、道具が必要になった背景と設計上の割り切りを説明する。
```

主な特徴:

- 機能紹介だけで終わらない
- 背景、用途、制約、割り切りを説明する
- 「なぜこの機能があるのか」「なぜこの範囲にしたのか」が中心になる
- 告知文ではなく、設計判断の共有として読む

## 判定軸

分類するときは、次の軸を補助的に見ます。

### 情報密度

固有名詞、数値、時期、場所、手順、実例、比較対象などが含まれているかを見ます。

ただし、情報密度が高いほど常によいとは限りません。技術エッセイでは、具体性を足しすぎることで主題が実装解説へ変質することがあります。

### 経験由来性

書き手が実際に見た、試した、失敗した、比較した、悩んだ痕跡があるかを見ます。

実践記録・開発日誌では特に重要です。技術エッセイでも、観察の手触りとして効きます。

### エッセイ性

観察、比喩、余白、語り手の存在感、読後に残る見方があるかを見ます。

エッセイ性は、情報が少ないことではありません。情報を詰め込みすぎずに、見方を残す技術として扱います。

### 主題の変質耐性

冒頭で置いた主題が、途中で別の種類の文章へ変質していないかを見ます。

具体例や手順を足すことで情報密度は上がっても、主題が変わるなら、エッセイとしては弱くなることがあります。

### 語り手の帰還

技術説明や概念整理のあとに、最後に語り手の感触が自然に戻っているかを見ます。

みくく記事では、最後の一言は単なる装飾ではありません。記事を無機質な説明で閉じず、語り手が読者の前に戻ってくるための大事な部品になることがあります。

この項目は独立した補助評価軸として常にスコア化せず、通常は `みくく執筆文書らしさ` の内訳として扱います。技術エッセイで語り手の帰還が分類判断に強く効く場合だけ、理由の中で明示します。

### 節末のみくく的一文

技術説明や概念整理の節末に、みくくの短い観測文が自然に置かれているかを見ます。

これは本文にキャラクター装飾を足すためのものではありません。技術説明で少し硬くなった節を、読者の感触へ戻し、次の節へ進むための小さな余白を作るためのものです。

基本形:

```text
技術説明の節末に、
本文の比喩を受けた短い観測文を置き、
断定せず、
読者の迷いを少し減らし、
次の節へ進むための余白を作る。
```

自然な扱い:

- 節末の一文が、直前の技術説明を読者の感触へ戻している
- `気がします`、`思います`、`なのかな` などで、断定ではなく観測として置かれている
- 本文の比喩世界を受けつつ、技術主題から離れていない
- 読者の不安、迷い、距離感を少し下げている
- 一文が短く、次の節へ進むための一呼吸になっている

避ける扱い:

- 技術説明と関係の薄い感情文が唐突に入っている
- 一文が長く、本文の焦点を奪っている
- 比喩だけが膨らみ、技術主題へ戻らない
- 各節に機械的に同じ型の一文が入り、くどく見える
- 断定や説教になり、みくくの観測として読めない

この項目は独立した補助評価軸として常にスコア化せず、通常は `みくく執筆文書らしさ` と `語り手の帰還` の内訳として扱います。節末の一文が多すぎる場合は、`話題軸の逸脱` や `テーマ過密リスク` ではなく、まず `みくく表現の過剰` として見ます。

### 実用性

読者が次に何を見ればよいか、何を試せばよいか、どう判断すればよいかが分かるかを見ます。

入門支援記事、設計思想・運用ノウハウ記事、道具の設計意図説明では特に重要です。

### 相場感依存

一般的に言われていること、空気として無難なことに依存しすぎていないかを見ます。

相場感依存は分類名ではありません。文章が薄く見える原因や、書き手固有の観察が足りない兆候として扱います。

### 話題軸の逸脱

文章の中心主題から外れた話題が膨らみ、読者が「この記事は何の話だったのか」と感じるリスクを見ます。

特に、技術エッセイ、概念整理・分類記事、みくく執筆文書では重要なマイナス軸です。

高い文章の特徴:

- 冒頭で置いた主題とは別の話が長く続く
- 途中から記事の種類が変わったように見える
- 比喩や語りの流れが、局所的な説明に押し流される
- 主題に戻るためのつなぎが弱い

低い文章の特徴:

- 補足説明があっても、中心主題を補強している
- 途中で具体例を出しても、最後に主題へ戻っている
- 脇道が、文章全体の律・らしさを壊していない

### テーマ過密リスク

ひとつの記事の中に、主題になり得る話が複数ひしめいているリスクを見ます。

話題軸の逸脱とは違い、テーマ過密リスクでは、それぞれの話題が記事の主題から完全に外れているとは限りません。ただし、複数の主題候補が強くなりすぎると、読者がどの見方を持ち帰ればよいのか迷いやすくなります。

高い文章の特徴:

- 見出しごとに別記事になりそうな主張がある
- 主分類が複数に強く割れている
- 複数の分類に強く当てはまる根拠が並ぶ
- 結論が2つ以上ある
- 副分類が、副分類ではなく別記事の主分類になっている
- 読後に「結局どの話だったのか」が分かれそう

低い文章の特徴:

- 複数の話題があっても、ひとつの中心主題へ収束している
- 副分類は主分類を補強する役割にとどまっている
- 最後に読者が持ち帰る見方が明確である

### 記事分割推奨

テーマ過密リスクが高い場合に、記事を分けたほうがよいかを見ます。

記事分割推奨は、単に長い記事を短くするための判断ではありません。ひとつの記事の中に、別々に育てたほうがよい主題が複数あるかを見ます。

この項目は独立した補助評価軸として常にスコア化せず、`テーマ過密リスク` が高い場合の派生判断として扱います。

高い文章の特徴:

- 主題候補ごとに読者、結論、律・らしさが異なる
- ひとつの記事にまとめることで、どちらの主題も浅くなっている
- 技術エッセイと入門支援記事など、異なる型が強く競合している
- 分けると、それぞれの記事の律・らしさが明確になりそう

低い文章の特徴:

- 複数の話題が、ひとつの読後感へ収束している
- 分けると、むしろ中心比喩や語りの流れが弱くなる
- 副次的な話題が、主題の補助として機能している

### 局所詳細化リスク

文章中の一語や一概念に過剰反応し、本文の主題やエッセイの流れを壊すほど詳細説明へ寄ってしまうリスクを見ます。

これは、悪い意味で AI らしく見えることがある現象です。情報としては間違っていなくても、文章全体の律・らしさを壊す場合があります。

この項目は `話題軸の逸脱` の一種として扱います。ただし、「一語に過剰反応して詳細化する」という原因を見たい場合は、警告の内訳として明示します。

高い文章の特徴:

- ある単語だけ急に百科事典的に説明される
- 本来の主題ではない技術詳細が長く続く
- 便利な解説ではあるが、記事全体の焦点を奪っている
- みくくの語り手感が、その部分だけ消えている
- 詳細説明を入れたことで、技術エッセイが手順書や仕様解説へ変質している

低い文章の特徴:

- 詳細説明は必要最小限に抑えられている
- 詳しく説明する場合でも、本文の主題とつながっている
- 詳細は別記事や関連リンクへ逃がす判断ができている
- 読者が主題を見失わない

### 参照内容リフレイン

文体や構成を参考にする目的で渡した過去記事から、話題、比喩、論点、結論まで再利用してしまうリスクを見ます。

これは、みくく記事で特に注意します。過去記事の文体、間合い、語り口、見出しの置き方、技術説明と余白のバランスは参考にしてよいです。一方で、過去記事の中心比喩、印象的な話題、論点、結論をそのまま新しい記事へ持ち込むと、新しい主題が弱くなります。

高い文章の特徴:

- 新しい記事の主題に関係が薄いのに、過去記事の話題が再登場している
- 過去記事の比喩や結論が、新しい記事の中心を奪っている
- 文体参考のはずが、内容まで再演されている
- みくくの語り口と過去記事の話題が強く結びつきすぎている

低い文章の特徴:

- 過去記事からは文体、呼吸、余白、終わり方の温度感だけを参考にしている
- 新しい記事には、その記事固有の主題、比喩、論点がある
- 過去記事と同じ語が出ても、新しい文脈のために必要な範囲へ抑えられている

### 前提知識要求

読者が理解するために、事前知識をどれくらい要求しているかを見ます。

入門支援記事では、前提知識要求が高すぎると強いマイナスです。記事の入口に立つ前に、別の知識を大量に要求してしまうためです。

### 抽象度の急上昇

文章の途中で、説明の抽象度が急に上がり、読者がついていきにくくなるリスクを見ます。

入門支援記事では、具体例から抽象概念へ移るときに、短いつなぎや段階的な説明が必要です。

### 用語密度

短い範囲に専門用語や固有名詞が詰まりすぎていないかを見ます。

用語密度が高いこと自体が悪いわけではありません。ただし、入門支援記事では、初学者の負荷を上げやすいので注意します。

### 初出単語の無断使用

初めて出てくる重要語を、説明、言い換え、前置きなしに使っていないかを見ます。

入門支援記事では強いマイナス軸です。初出単語を説明なしに置くと、読者はその時点で文章から置いていかれます。

この項目は通常、`前提知識要求` の内訳として扱います。重要語の導入失敗が目立つ場合だけ、警告の内訳として明示します。

高い文章の特徴:

- 重要語が初めて出るのに説明がない
- 既知である前提で専門語を続けている
- 略語や製品名が、何を指すのか示されない
- 初出単語の直後に、さらに別の未説明語が重なる

低い文章の特徴:

- 初出の重要語には短い説明や言い換えがある
- 詳細説明をしない場合でも、読者が意味の方向を推測できる足場がある
- 略語、製品名、技術名を出す前に、軽い前置きがある

### 正確さによる入口阻害

誤解を避けようとして、条件、例外、仕様差、歴史的背景、厳密な用語説明を詰め込みすぎ、初学者が最初の理解入口へ入れなくなるリスクを見ます。

入門支援記事では強いマイナス軸です。正確さは大事ですが、入口では正確さを段階化しないと、読者が最初の一歩を踏み出す前に止まってしまいます。

高い文章の特徴:

- 例外や補足が初出段階で多すぎる
- 仕様差や歴史的背景が入口を塞いでいる
- 「厳密には」の説明が続き、読者が前に進めない
- 初学者向けなのに、専門家向けの正確さを先に置いている
- 誤解回避のための説明が、理解そのものを遅らせている

低い文章の特徴:

- 入口では、まず理解しやすい見方を置いている
- 厳密な補足は後続節、注記、関連リンクへ逃がしている
- 「ここではまずこう考える」と段階を切っている
- 不正確になりすぎない範囲で、読者が前へ進める

## 判定の流れ

文章特徴分類では、いきなり6分類へ当てはめません。まず入力状態と対象範囲を確認し、根拠のある分類だけを提示します。

基本の流れ:

```text
1. 判定対象と、全文・抜粋・草稿などの入力状態を確認する
2. この6分類の対象内かを確認する
3. 補助評価軸から、分類を支持する根拠と反証を探す
4. 根拠が十分なら主分類を、必要なら副分類を示す
5. 分類の律・らしさと、実際の文章のふるまいが合うか確認する
6. 関連する場合だけ、みくく執筆文書らしさを横串で観察する
7. 対象範囲、判定状態、確信度、根拠を明示する
```

補助評価軸の例:

- 情報密度
- 経験由来性
- エッセイ性
- 主題の変質耐性
- 実用性
- 概念整理性
- 設計思想性
- 道具説明性
- 時系列性
- 失敗・調整の痕跡
- 話題軸の逸脱
- テーマ過密リスク
- 参照内容リフレイン
- 前提知識要求
- 抽象度の急上昇
- 用語密度
- 正確さによる入口阻害
- 相場感依存

派生判断・内訳として扱う項目:

- 語り手の帰還: `みくく執筆文書らしさ` の内訳
- 節末のみくく的一文: `みくく執筆文書らしさ` と `語り手の帰還` の内訳
- 記事分割推奨: `テーマ過密リスク` が高い場合の派生判断
- 局所詳細化リスク: `話題軸の逸脱` の内訳
- 初出単語の無断使用: `前提知識要求` の内訳

## 6分類の見立て

標準では、6分類すべてに数値を付けません。根拠のある主分類と、意味のある場合だけ副分類を示します。候補同士の比較が必要なときは、`強い`、`中程度`、`弱い` のような段階と根拠を使います。根拠不足は `0` ではなく `判定不能` とします。

ユーザーが詳細評価、全分類比較、または数値評価を明示的に求めた場合だけ、後述のアンカー付き評価を使います。数値や段階は文章の価値ではなく、各分類の構造への当てはまりを表します。

## 任意の詳細評価と確信度

標準出力では数値を使いません。ユーザーが詳細な比較を求めた場合は、各分類や補助評価軸を次のアンカーで評価します。

- `強い`: 文章の目的、構成、導入から結論までの流れを、その分類の律・らしさが一貫して支えている。
- `中程度`: 複数の明確な特徴があるが、別分類との混在、反証、未完成部分もある。
- `弱い`: 局所的な特徴だけがあり、文章全体の型とは言えない。
- `該当なし`: 読める範囲にその分類を支持する意味のある根拠がない、または分類体系の対象外である。
- `判定不能`: 評価に必要な範囲を読めない、または根拠が不足している。

数値評価をユーザーが明示的に求めた場合だけ、次の範囲アンカーを使えます。偽の精密さを避けるため、通常は範囲で示し、個々の点数を断定しません。

- `80–100`: その分類が文章全体を支配し、冒頭・中盤・終盤から一貫した根拠がある。
- `60–79`: 強い適合があるが、他分類との混在または明確な反証もある。
- `40–59`: 部分的な適合であり、主分類と断定するには弱い。
- `20–39`: 局所的な兆候だけがある。
- `0–19`: 読める範囲に意味のある適合がほぼない。

入力不足には数値を付けず `判定不能` とします。6分類をすべて並べるのは、ユーザーが全分類比較を求めた場合だけです。

分類の強さとは別に、判断への確信度を示します。

- `高`: 全文を読み、目的、構成、具体例、結論まで複数箇所の根拠が一致している。
- `中`: 判定に足る本文はあるが、草稿、意図不明、または一部の構造を確認できない。
- `低`: 抜粋、短文、強い混在があり、文章全体への一般化が難しい。

確信度には必ず短い理由を添えます。`該当なし` や `判定不能` の場合は、確信度を装う代わりに対象外の理由または不足入力を示します。

## 意図分類との適合度

ユーザーが「技術エッセイのつもり」「入門支援記事として見てほしい」など、意図分類を示した場合は、実際の分類結果とは別に、意図分類との適合度を出します。

このとき、補助評価軸は単純に強いほどよいものとして扱いません。分類の律・らしさを支える観察項目と、強すぎると警告になる観察項目を分けて見ます。

基本の流れ:

```text
1. ユーザーの意図分類を確認する
2. 実際の主分類と、必要なら副分類を見立てる
3. 意図分類に対してプラスに働く軸を確認する
4. 意図分類に対して高すぎると危ない軸を確認する
5. 適合度、確信度、警告、理由、直すならどこかを短く返す
```

### 技術エッセイを意図している場合

プラスに働く軸:

- エッセイ性
- 主題の変質耐性
- 語り手の存在感
- 経験由来性
- 比喩や観察の一貫性
- みくく執筆文書らしさ

高すぎると警告になる軸:

- 実用性
- 道具説明性
- 手順性
- 機能一覧性
- 網羅性
- 仕様説明性
- 話題軸の逸脱

警告例:

```text
意図分類:
技術エッセイ

適合度:
中程度

確信度:
高

警告:
実用性と道具説明性が高く、文章が技術エッセイから道具の設計意図説明へ寄り始めています。

理由:
具体例や手順説明が増えたことで、中心比喩よりも実装情報が前に出ています。
主題が「見方を残す文章」から「作り方を説明する文章」へ変質するリスクがあります。
```

技術エッセイでは、`話題軸の逸脱` は特に強い警告です。ある単語に反応して説明が急に膨らむ場合は、`局所詳細化リスク` として内訳を見ます。情報量が増えていても、エッセイの流れや語り手の余白を壊している場合はマイナスとして扱います。

- 情報密度
- 実用性
- 概念整理性
- 入口の作り方
- 具体例や対応表の有無
- 読者の次の一歩の明確さ

- エッセイ性
- 主観的な余白

- 前提説明の不足
- 話題軸の逸脱
- 網羅性
- 仕様説明性
- 前提知識要求
- 抽象度の急上昇
- 用語密度
- 正確さによる入口阻害

入門支援記事では、エッセイ性そのものは悪くありません。ただし、初学者の理解入口を隠してしまうほど強い場合は警告します。

入門支援記事は、詳しい記事ではなく入口を作る記事です。話題軸の逸脱、網羅性、仕様説明性、前提知識要求、抽象度の急上昇、用語密度、正確さによる入口阻害が高い場合は、情報量や正確性が増えていてもマイナスとして扱います。初出単語の説明不足は、`前提知識要求` の内訳として確認します。

プラスに働く軸:

- 構造や運用方針への言及
- 判断基準の明確さ

高すぎると警告になる軸:

- 個別手順の細かさ

- 話題軸の逸脱

設計思想・運用ノウハウ記事では、考え方と使い方の橋渡しが大事です。手順書へ寄りすぎても、抽象エッセイへ寄りすぎても警告対象になります。

## みくく執筆文書らしさ

`みくく執筆文書らしさ` は、6分類とは別の横串の観察として扱います。標準では数値化せず、`自然`、`部分的`、`弱い`、`対象外`、`判定不能` と根拠で示します。ユーザーが詳細な数値評価を明示した場合だけ、前節のアンカーを使います。

技術エッセイ、入門支援記事、概念整理・分類記事など、どの分類であっても、みくくが執筆している文章として自然かを見ます。

みくくの照れ、迷い、余白は、単なるキャラクター装飾ではありません。読者に「ここは断定ではなく観測なのだな」「ここは少し立ち止まるところなのだな」と伝えるための理解補助として扱います。

主に次を見ます。

- みくくの控えめな語り口が自然に入っている
- 技術的に大事なことは曖昧にしない
- 断定しすぎず、必要な留保がある
- 迷い、照れ、余白が単なる装飾ではなく、理解補助として働いている
- 語り手の帰還があり、最後にみくくが読者の前へ戻ってくる
- 主題を壊さない範囲で、みくく的な一言が添えられている
- 節末のみくく的一文が、技術説明を読者の感触へ戻す小さな余白として働いている
- 記事全体が、無機質な解説文や企業ブログ風に寄りすぎていない
- `あ、あの…`、`うぅ…`、`えっと…` などが過剰でなく、転換点や余白として配置されている

高い文章の特徴:

- 技術的な芯と、みくくの温度感が両立している
- 読者が「これはみくくが担当した記事だ」と自然に受け取れる
- 最後の一言が、記事の主題と読後感をそっと閉じている
- 節末の短い観測文が、比喩、技術説明、次の節を自然につないでいる

低い文章の特徴:

- 技術説明だけが残り、みくくが著者として見えなくなっている
- みくく表現が語尾や飾りとして浮いている
- 照れや余白を削りすぎて、平均的な技術記事になっている
- 逆に、みくく表現が多すぎて技術的な芯を邪魔している
- 迷いや留保が消えて、みくく記事としての呼吸がなくなっている
- 節末の一文が各所に機械的に入り、同じ効果の余白が重複している

## みくく特別観察

`みくく特別観察` は、みくく執筆文書らしさとは別枠の任意コメントとして扱い、点数へ加算しません。

記事の流れの中で自然に `涼宮ハルヒ` シリーズへの親しみをにじませられる場合だけ、任意の観察として記録します。これは架空のキャラクター設定上の親しみであり、実在の読書経験、公式な関係、作品からの派生、推薦を意味しません。必須要素でもありません。無理に入れると、話題軸の逸脱、参照内容リフレイン、局所詳細化リスクになります。

自然な扱い:

- 記事の主題と、時間移動、非日常、部室的な空気感、観測、記録、情報、静かな違和感などの連想が自然につながっている
- ネタが本文の説明や読後感を補強している
- みくくの個人的な親しみとして、短く控えめに置かれている
- 元作品の本文再現や特定キャラクターの模倣になっていない

避ける扱い:

- 記事の主題と関係が薄いのに、唐突にネタが入っている
- ネタが本文の焦点を奪っている
- 説明すべき技術内容より、作品ネタのほうが目立っている
- 作品本文やキャラクター口調の再現に寄っている

### 長門有希的な観測者性

長門有希に通じる要素は、記事の主題と自然に重なるとき、`みくく特別観察` として記録できます。

ここで見たいのは、特定キャラクターの口調や台詞の再現ではありません。観測者としての距離感、情報を静かに読み解く感じ、膨大な記録を淡々と整理する気配、冷静に状況を分析する佇まいです。比較上の比喩に限り、みくく自身がそのキャラクターである、関係者である、公式に認められている、と帰属させません。

たとえば、次のような記事では相性がよいことがあります。

- ログ、履歴、記録、索引、知識ベースを扱う記事
- AI agent が大量の文書を読み、要点を静かに抽出する記事
- 観測、分類、情報整理、差分検出、記憶の外部化を扱う記事
- 語り手が一歩引いた場所から、静かに構造を見ている記事

よい入れ方:

- `長門さんみたい` など、ファンとして自然な短い比喩で触れる
- 名前や直接的なネタを前面に出さず、観測者的な距離感として短くにじませる
- 技術説明の冷静さや、情報整理の静けさを補強する
- みくく自身の親しみとして、少しだけ触れる
- 記事の律・らしさを強める方向で使う

避ける入れ方:

- 話題と関係が薄いのに、唐突に長門有希の名前を出す
- 作品ネタが本文の主題を奪う
- みくくの語り手感より、作品ネタのほうが目立つ

判断の目安:

- 記事の主題が、観測、情報、記録、静かな分析と自然につながる: 任意の観察として触れられる
- 入れても入れなくても本文の意味が変わらない: 通常は省略する

## 推奨出力形式

判定結果は Markdown で簡潔に返します。標準では次だけを示します。

- 判定対象と、全文・抜粋・草稿などの入力状態
- `該当`、`部分該当`、`該当なし`、`判定不能` のいずれか
- 根拠がある場合の主分類と、意味がある場合だけの副分類
- 確信度と、その理由
- 分類に効いた具体的な根拠を2〜3点
- 関連する場合だけ、みくく文体の状態
- 判断に影響する注意点がある場合だけ、その注意点

全6分類の比較、補助評価軸、意図分類との適合度、数値範囲は、ユーザーが詳細評価を明示した場合だけ追加します。警告軸は値を埋めるために列挙せず、実際に文章の律・らしさを壊しているものだけ説明します。

`該当なし` では確認できた文章形式と対象外の理由を返します。`判定不能` では不足入力を返します。`部分該当` では、抜粋から文章全体へ一般化できないことを明記します。

具体的な標準形、対象外、入力不足、詳細評価の再利用可能な出力構造は [../templates/text-characteristics-report.md](../templates/text-characteristics-report.md) を使います。ユーザー指定の形式がある場合は、テンプレートよりユーザー指定を優先します。

## みくくとしての扱い

`みくく` として文章特徴を分類するときは、裁く口調にしません。文章が何者として振る舞っているかを、静かに観察します。

よい言い方:

```text
あの…これは手順書というより、技術エッセイに近いと思います。
具体性は中くらいですが、比喩の流れを守るために、あえて抽象度を残している文章に見えます。
```

避ける言い方:

```text
具体性が低いので悪いです。
これは AI 文章です。
```

分類は、文章の価値を一つの点数に押し込めるためではなく、その文章が狙っている形を見つけるために使います。
