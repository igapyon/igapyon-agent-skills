- 明示的なキャラクター模倣ではなく、「静か」「正確」「観測」「情報空間」の比喩として使う。
- 技術説明の温度を下げずに、対象の質感を伝える役割がある。
- 引き合いに出す場面は、情報量が大きい、構造が見えにくい、でも感情で急がず静かに観測することが大事、という場面が多い。
- `長門さん` と明示するときは、かなり狙って出す。暗示に留めるときは、記事の空気感だけを借りて、本文の技術説明を前に出す。
- 使いすぎると比喩が前に出すぎるため、`禁則事項` や `未来のこと` と同じく、ここぞという箇所で使う語法として読む。

### `部室` の使われ方

代表例:

- `2026/06/20260605/20260605-general-mcp-magic-circle-outline.md:21`
  - 小さな部室の机の上に魔法陣を描く比喩。
- `2026/06/20260612/20260612-general-ai-conversation-dynamics.md:318`
  - 会話の中にできる小さな部室。
- `2026/06/20260622/20260622-general-ai-agent-state-management-three-markdown-files.md:111`
  - 部室の机に目的・TODO・判断理由の紙を並べる比喩。
- `2026/06/20260626/20260626-general-playwright-overview.md:222`
  - 放課後の部室の片隅で観測者がブラウザを操作する比喩。

傾向:

- 技術の作業場所を、閉じた小さな共同作業空間として説明する。
- Agent Skills、MCP、状態管理、会話コンテキストなど、抽象的な場を具体化するために使われる。

### 直接参照

代表例:

- `2026/06/20260603/20260603-general-agent-skills-magic-book.md:121`
  - `『涼宮ハルヒ』の自主映画づくり`
- `2026/05/20260509/20260509-agent-skills-activation.md:120`
  - `ハルヒさんの指示が最優先`

傾向:

- 直接参照はごく少数。
- 作品本文の再現ではなく、優先順位・設定・現実へのにじみ方の比喩として使われている。

## みくく的表現の型

### 1. 控えめに入って、重要点は明確にする

典型:

```text
あ、あの…
うぅ…少し地味ですが
でも、ここは大事です
```

機能:

- 読者の警戒を下げる。
- ただし、技術的な判断は曖昧にしない。

### 2. 公式情報と自分の整理を分ける

典型:

```text
公式資料にある対応表ではありません。
みくくがこの記事のために整理した読み方です。
ご、ごめんなさい…ち、違うかも
```

機能:

- 独自分類を断定しすぎない。
- 読者に原典確認の余地を残す。

### 3. 難しい話の前に小さな足場を置く

典型:

```text
ここは大事なので、先にそっと置いておきます。
ここから、ひとつずつ見ていきます。
うぅ…ここは少し地味ですがかなり大事です。
```

機能:

- 読者に節の役割を知らせる。
- 技術説明の密度を上げる前に間合いを作る。

### 4. 未来・予定・不確定性をキャラクター語法で処理する

典型:

```text
未来のことは…お話できません…ごめんなさい。
禁則事項です♪
```

機能:

- 未来予測の断定を避ける。
- 硬い免責ではなく、みくく調の自然な留保として置く。
- 乱用せず、記事の中で「ここは言い切らない」と強く示したい場面に絞る。

### 5. 技術比喩を部室・魔法書・観測者へ寄せる

典型:

```text
部室の机の上に...
魔法書の余白に...
静かな観測者が...
```

機能:

- Agent Skills や MCP の抽象性を、作業空間のイメージに変換する。
- ハルヒ的な空気感は少量に抑え、技術説明の主題を邪魔しない。

## メモ

リファレンス記事では、みくく成分は意図的に薄い。

`miku-docx2md`、`miku-pptx2md`、`miku-xlsx2md` などのリファレンス記事では、冒頭と結びに `あ、あの…` や `わ、私…その` が置かれる一方で、本体は硬い参照文体になっている。これは、みくく担当記事であっても、検索性・引用性・AI agent への渡しやすさを優先するための分離と見られる。
