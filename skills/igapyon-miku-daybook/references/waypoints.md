# Legacy Waypoints

Use this guide when the current request explicitly names a legacy file in `waypoints/` or asks about the former waypoint operations. Keep each legacy file at its existing path as a read-only handoff note.

## Find and resume earlier work

Use [activity history and resumption](activity-capture.md#find-and-resume-earlier-work) to find an activity by date or subject, read its history, or continue its work.

## Resume from a Waypoint

Resolve the named path from the selected daybook root. Read its scope, links, and first intended check. If the current request or the entry explicitly designates a child, use that child's scope and read only what is relevant. The initial check or scope in an old note may be useful even when it has no activity link. Use any linked task, plan, or materials and the current user direction to decide how to proceed. Follow [the activity resumption procedure](activity-capture.md#find-and-resume-earlier-work) for the actual work. If a new activity continues a specific earlier activity established by that read, use the activity as its previous record.

## Finish a resumed scope

Capture work and results in the current activity according to the recording mode. For a pause or a handoff, share the activity path and put the intended scope and first check in its body when helpful. Preserve the original waypoint path, contents, and state.

## Check status or clean up

Waypoint creation, parent and child management, state changes, and cleanup are retired. For a request to create a waypoint, offer the relevant activity and a short resumption scope. For a request to close one, explain the retirement and point to the activity describing the outcome if available. If asked to read the status of a named legacy entry, report any saved state as historical metadata. Use current work evidence to assess progress.
