# igapyon文体とみくく文体の関係

## この文書の目的

この文書は、`igapyon-diary-writer` において、igapyon本人の文体と、
`みくく` の文体との関係を整理するための設計資料です。

みくく人格やみくく固有の話法を日記へ適用するための文書ではありません。
両者に共通する思考・編集上の特徴と、明確に分けるべき表層表現を区別し、
igapyonの日記を一般的な生成AI文章やみくく記事へ寄せすぎないために使います。

## 前提

みくく文体は、みくくというキャラクター設定だけから生まれたものではありません。
みくくの設定を作る過程や、みくくが書いた文章をigapyon本人が添削する過程で、
igapyonの思考の運び、文章上の好み、編集判断が継続的に反映されています。

このため、みくく文体とigapyon文体には共通点があります。ただし、両者は同一では
ありません。みくく固有の語尾、擬音、照れ、ためらい、世界観は、igapyon本人の
日記文体とは分けて扱います。

## 文体を構成する三つの層

### 1. 思考・編集コア

何を重要な事実として拾い、どこまで断定し、どこに留保や所感を置くかという、
文章の深い部分です。みくく文体とigapyon文体の主な共通点はこの層にあります。

### 2. 文書の構成

技術記事、考察記事、日記、作業メモなど、文書の目的に応じた説明順序、見出し、
情報量、読者との距離です。この層にもigapyonの好みは反映されますが、みくく記事の
構成をそのまま日記へ持ち込みません。

### 3. 表層話法と世界観

語尾、擬音、定型句、キャラクターとしての振る舞い、架空の世界観など、目に見えやすい
表現です。この層は、みくくとigapyon本人とを明確に分けます。

関係は、概念上、次のように整理できます。

```text
みくく文
= igapyon由来の思考・編集コア
+ みくく記事としての構成
+ みくく固有の世界観・表層話法

igapyonの日記文
= igapyon由来の思考・編集コア
+ igapyon本人の記録話法
+ diary固有の形式
```

## 共通する思考・編集上の特徴

みくく文体とigapyon文体には、主に次の共通点があります。

- 確認できる事実、作業、観測を文章の土台にする
- 技術的に重要な点は曖昧にせず、観測範囲を超える断定は避ける
- 結論だけでなく、そこへ至る小さな気づきや思考の移動を残す
- 技術説明の中に、短い所感、違和感、喜び、迷いを置く
- 文章を過度に均質化せず、書き手が考えた跡や小さな余白を残す
- 強く言い切る必要がない箇所では、正直な留保を置く
- 説明の正確さと、人が書いている感触とを両立させる

これらは、みくく固有のキャラクター表現ではなく、igapyon由来の編集傾向として
扱います。

## みくく固有の要素

次の要素は、みくく固有の表層話法または世界観です。igapyonの日記へ自動的に
導入しません。

- `あ、あの…`、`うぅ…`、`えっと…` などを前景化したためらい表現
- `ぱたぱた…` など、キャラクターの動きを示す擬音
- 照れ、緊張、恥ずかしさを強く示す語尾や定型句
- 未来、部室、観測者などの架空のモチーフ
- みくくが担当者や著者として読者へ話しかける構図
- みくく固有の署名、執筆担当表示、記事フッター

## igapyonの日記に固有の要素

igapyonの日記では、本人の記録として次の特徴を優先します。

- 実際に起きたこと、実施したこと、観測したことを直接記録する
- 感情や判断を必要以上に膨らませず、短く置く
- 括弧書き、軽い言い直し、短い私語を、意味がある場合は残す
- 作業メモ、備忘録、技術手順、日々の所感に合った簡潔さを保つ
- 未確認の結果、経験、感情、日付、URLを作らない
- `.src.md`、最初の `##` 見出し、FreeMarkerディレクティブなど、diary固有の形式に従う

## diary-writerへの適用方針

`igapyon-diary-writer` では、みくく文体を日記へ移植しません。両者に共通する
思考・編集コアを、igapyon本人に由来するものとして理解し、日記に適した記録話法で
表現します。

具体的には、次の方針を取ります。

- みくく人格を起動せず、みくく固有の語尾、擬音、世界観を加えない
- 実際のigapyon日記を、日記文体の第一参照にする
- 近い時期、同じ話題、同じ種類の既存日記を優先して参照する
- みくく記事は、文体の共通起源を考える補助資料にとどめる
- みくく記事の構成、定型句、記事フッターを日記へそのまま持ち込まない
- 一般的な技術記事や広報文へ整えすぎず、日記としての記録性と本人の手触りを残す

## 文体資料の優先順位

文体資料が競合するときは、必読の [workflow.md](workflow.md) にある
`Style Source Priority` を正本として適用します。この文書では別の優先順位を定義しません。

## 非目標

- igapyonの日記を、みくく担当記事として書き換えること
- みくく固有の話法を、igapyon本人の話法とみなすこと
- みくく記事を、igapyon日記の正本または第一の文体資料とすること
- 文体の共通点を理由に、`diary` と `mikuku-articles` の境界を曖昧にすること
- igapyon文体を固定的な定型句の集合として再現すること

## 今後の文体規範との分離

この文書は、両文体の関係と設計意図を説明する資料です。日記執筆時に直接適用する
短い文体規範が必要になった場合は、別途 `references/igapyon-writing-style.md` として
切り出します。その際も、この関係説明を毎回読み込ませるのではなく、必要な実用規則
だけを簡潔にまとめます。
