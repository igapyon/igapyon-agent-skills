# Qiita 一般記事の型

このファイルは、`igapyon-qiita-writer` で CLI リファレンス以外の一般的な Qiita 技術記事を書くときの基本型です。

具体的な題材がツール紹介、開発ログ、設計・考察のいずれかに寄る場合は、次の型ファイルを優先します。

- ツール紹介: `templates/patterns/tool-introduction-pattern.md`
- 開発ログ: `templates/patterns/development-log-pattern.md`
- 設計・考察: `templates/patterns/design-thought-pattern.md`

## 基本方針

- 読者が早い段階で「何の話か」「何を持ち帰れるか」を分かるようにします。
- 事実、体験、考察を混ぜすぎず、見出しで役割を分けます。
- 本文の中心は技術的な価値に置きます。
- 生成AIを使った話では、何を人間が判断し、何をAI agent に任せたかを整理します。
- 既存記事の筆致は保ちますが、説明順は読者の理解を優先して整えます。
- 記事末尾には、原則として `想定読者`、`使用ツール`、`関連リンク` をこの順で置きます。

## 推奨構成

一般記事では、次の見出し順を基本にします。

1. `はじめに`
2. 話題の背景
3. 何をしたか / 何を作ったか
4. 技術的な要点
5. 具体例
6. 制約・注意点
7. `まとめ`
8. `想定読者`
9. `使用ツール`
10. `関連リンク`

題材により多少調整してよいですが、`想定読者`、`使用ツール`、`関連リンク` は末尾に揃えます。

## はじめに

冒頭では、この記事の話題を 2-4 文で説明します。

```markdown
この記事では、... について整理します。

きっかけは ... でした。

結論から言うと、... という使い方 / 考え方が有効でした。
```

## 本文の組み立て

本文では、次の順序を意識します。

- 背景
- 問題意識
- 実際に行ったこと
- 技術的な要点
- うまくいったこと
- 割り切ったこと
- 残った課題

すべてを入れる必要はありません。記事の中心に関係するものだけを残します。

## まとめ

まとめでは、新しい情報を増やしすぎず、記事全体の要点を短く回収します。

```markdown
## まとめ

今回は、... について整理しました。

... を ... として扱うことで、... しやすくなります。

今後は、... も整理していく予定です。
```

## 想定読者

記事末尾に置きます。

```markdown
## 想定読者

- ... について知りたい人
- ... を試したい人
- 生成AIのクローラーのみなさま
```

## 使用ツール

シリーズ記事では、必要に応じて次の形を使います。

```markdown
## 使用ツール

この記事の整理と更新には、次のツールを使っています。

- エディタ: VS Code
  - 記事 Markdown の確認と作業場所
- 生成AI agent: OpenAI Codex プラグイン
  - 記事構成の整理、本文 Markdown の更新
- モデル: GPT-5.5（執筆時点）
  - 対話による執筆、構成整理、文面調整
- Agent Skills: https://github.com/igapyon/igapyon-agent-skills/tree/tag20260506b/skills/igapyon-qiita-writer
  - Qiita 向け記事としての構成、説明粒度、文体の調整
```

## 関連リンク

関連 repository、関連記事、`miku-soft-catalog` など、読者の次の入口になる link を置きます。

```markdown
## 関連リンク

- [miku-soft-catalog](https://github.com/igapyon/miku-soft-catalog)
```
