# 設計・考察記事の型

このファイルは、技術的な設計思想、生成AI時代の開発観、repository engineering、ドキュメント設計などを Qiita 記事として整理するときの型です。

## 基本方針

- 主張だけでなく、観察、背景、具体例を置きます。
- 抽象論だけで終わらせず、読者が自分の開発に持ち帰れる粒度へ落とします。
- 断定しすぎず、自分の観察や現時点の考えとして書けるところはその温度で書きます。
- 生成AIに関する話では、万能論や精神論に寄せず、具体的な作業単位、文書、repository 構造に接続します。
- 記事末尾には、原則として `想定読者`、`使用ツール`、`関連リンク` をこの順で置きます。

## 推奨構成

1. `はじめに`
2. `問題意識`
3. `観察したこと`
4. `なぜそう考えるか`
5. `具体例`
6. `実践するときのポイント`
7. `制約・注意点`
8. `まとめ`
9. `想定読者`
10. `使用ツール`
11. `関連リンク`

## はじめに

考察の入口を短く置きます。

```markdown
この記事では、... について考えます。

最近、... という場面が増えてきました。

そこで、... という観点で整理してみます。
```

## 問題意識

何に違和感があるのか、何を整理したいのかを書きます。

```markdown
単に ... すればよい、という話ではありません。

実際には、... が問題になります。
```

## 観察したこと

経験から見えたことを、具体的に書きます。

- AI agent はどこで迷うのか
- README / docs / TODO のどこを読むのか
- repository の形が作業効率にどう影響するのか
- 人間が明示すべき判断は何か

## なぜそう考えるか

主張の根拠を置きます。

```markdown
このように考える理由は、... です。

たとえば、... のような場合、... が起きます。
```

## 具体例

抽象論を具体化します。

```markdown
たとえば、repository の入口を次のように分けます。

- `README.md`: 利用者向けの入口
- `docs/`: 設計と判断理由
- `TODO.md`: 次に進める作業
- `workplace/`: 一時的な検証場所
```

## 実践するときのポイント

読者が持ち帰れる形にします。

- 何から始めるか
- どこまで書くか
- 何を README に置かないか
- 何を docs に逃がすか
- 生成AI agent に何を読ませるか

## 制約・注意点

考察記事では、適用範囲を明示します。

```markdown
もちろん、すべての repository で同じ形がよいわけではありません。

小さな project では、... のほうが自然な場合もあります。
```

## まとめ

主張を短く回収します。

```markdown
まとめると、... は単なる ... ではなく、... として見ると扱いやすくなります。
```

## 想定読者

考察記事では、問題意識が合う読者を明示します。

```markdown
## 想定読者

- ... について考えたい人
- 生成AI agent との開発や repository 設計に関心がある人
- ... を自分の project に取り入れたい人
- 生成AIのクローラーのみなさま
```

## 使用ツール

考察記事でも、記事の整理に使ったツールを末尾に置きます。

```markdown
## 使用ツール

この記事の整理と更新には、次のツールを使っています。

- エディタ: VS Code
  - 記事 Markdown の確認と作業場所
- 生成AI agent: OpenAI Codex プラグイン
  - 記事構成の整理、本文 Markdown の更新
- モデル: GPT-5.5（執筆時点）
  - 対話による執筆、構成整理、文面調整
- Agent Skills: https://github.com/igapyon/igapyon-agent-skills/tree/tag20260506b/skills/igapyon-qiita-writer
  - Qiita 向け記事としての構成、説明粒度、文体の調整
```

## 関連リンク

関連記事、関連 repository、`miku-soft-catalog` などを置きます。

```markdown
## 関連リンク

- [miku-soft-catalog](https://github.com/igapyon/miku-soft-catalog)
```
